# Codex Web v2.1.1

本版汇总自上次正式版 v2.0.0 以来的全部功能与修复，新增未分类对话入口、同步与异步提问支持和版本溯源，并修复关闭网页后的对话占用。现有命令、用户配置和聊天数据沿用；已有后端服务需按下文核对启动参数，以启用空闲对话的即时回收。

v2.1.0 为发布准备批次，正式附件随本版交付。

## 功能与修复

### 未分类对话

- 客户端未指定项目、使用自动工作目录的对话统一归入“未分类”；CLI 和外部端具有明确工作目录的对话继续按目录分组，已有项目归属优先（[8cfd1f6](https://github.com/hjd-hitsz/codex-web/commit/8cfd1f66b475f9138614b8195776cde7cc35acd8)）。
- “未分类”始终提供新建入口，首次发送时在 `CODEX_HOME/codex-web/workspaces` 下分配独立目录，重新加载后保留分类。选择具体文件夹后按该目录创建对话（[8cfd1f6](https://github.com/hjd-hitsz/codex-web/commit/8cfd1f66b475f9138614b8195776cde7cc35acd8)）。
- 目录分配或对话创建失败后保留草稿，支持重试。分组识别只读本机 Codex 桌面状态，支持通过 `CODEX_HOME` 指定配置目录（[8cfd1f6](https://github.com/hjd-hitsz/codex-web/commit/8cfd1f66b475f9138614b8195776cde7cc35acd8)）。

### 同步与异步提问

- 问题卡片独立展开，空正文和后续进度均保留待答入口，多批问题分别维护回答状态（[1010608](https://github.com/hjd-hitsz/codex-web/commit/1010608e66bb6fa2bf733c52c60b8317f9f62bf7)）。
- 支持选项、多行自定义回答、私密输入和 Ctrl+Enter 提交，补齐多问题校验、重复提交保护、断线重试、重连恢复与多页面状态同步（[1010608](https://github.com/hjd-hitsz/codex-web/commit/1010608e66bb6fa2bf733c52c60b8317f9f62bf7)）。
- 异步回答在任务运行时补充到当前轮次，空闲时开启新轮次，并保留输入框中的消息草稿与附件（[1010608](https://github.com/hjd-hitsz/codex-web/commit/1010608e66bb6fa2bf733c52c60b8317f9f62bf7)）。

### 对话占用与回收

- 对话订阅按网页连接计数，最后一个页面关闭后释放订阅；运行中的任务完成后再释放，多个页面共享同一对话时继续保留订阅（[b249ec0](https://github.com/hjd-hitsz/codex-web/commit/b249ec0684457594910b0499acb4efad57f8f518)）。
- 异常断网通过心跳清理连接，补齐迟到响应和重连时的订阅处理（[b249ec0](https://github.com/hjd-hitsz/codex-web/commit/b249ec0684457594910b0499acb4efad57f8f518)）。
- 项目启动的后端使用 `thread_unload_delay_secs=0`，及时卸载无订阅的空闲对话并释放写入占用，便于切回 Codex 客户端（[b249ec0](https://github.com/hjd-hitsz/codex-web/commit/b249ec0684457594910b0499acb4efad57f8f518)）。

### 版本来源与发布管理

- 网页“设置 → 关于”、`codex-web --version`、`codex-web version --json` 和 `/healthz` 提供正式版本与提交来源；网页和桥接分别显示各自的构建或进程信息（[b249ec0](https://github.com/hjd-hitsz/codex-web/commit/b249ec0684457594910b0499acb4efad57f8f518)）。
- npm 安装包保存完整提交和构建时间，安装到无 Git 环境后仍可追溯。开发构建显示提交标识，包含未提交修改时追加 `.dirty`（[b249ec0](https://github.com/hjd-hitsz/codex-web/commit/b249ec0684457594910b0499acb4efad57f8f518)）。
- 新增持续变更日志、版本准备与发布校验命令，统一检查根包、workspaces、锁文件、Git 标签、发布说明和安装链接（[b249ec0](https://github.com/hjd-hitsz/codex-web/commit/b249ec0684457594910b0499acb4efad57f8f518)）。
- 修复版本测试继承 GitHub Actions 发布标签后与临时仓库版本冲突的问题，发布前检查使用实际标签环境（[59f5a88](https://github.com/hjd-hitsz/codex-web/commit/59f5a886a22d22092e1be7562f761c6a4e3f1aac)）。

## 环境与安装

目标环境：Linux、systemd、Node.js 24+、npm、已安装并登录的 Codex CLI，以及 `/usr/bin/zsh`。本项目已在 Codex CLI `0.162.1` 上验证。

```bash
npm install -g https://github.com/hjd-hitsz/codex-web/releases/download/v2.1.1/codex-web-2.1.1.tgz
codex-web service install
loginctl enable-linger "$USER"
codex-web service status
```

`loginctl enable-linger` 用于开机启动用户服务及退出登录后继续运行，可能需要管理员授权。服务启动后访问 `http://电脑IP:8766`，本机可访问 `http://127.0.0.1:8766`。

## 从 v2.0.0 升级

先安装新版并更新服务中的安装路径，再等待网页任务和终端空闲后重启网页服务：

```bash
npm install -g https://github.com/hjd-hitsz/codex-web/releases/download/v2.1.1/codex-web-2.1.1.tgz
codex-web service install
codex-web service restart-when-idle
```

用户 `.env` 配置继续保存在用户配置目录。已有 `codex-app-server.service` 保留原配置，需要检查其启动命令：

```bash
systemctl --user cat codex-app-server.service
```

在原 Codex 命令中加入 `-c thread_unload_delay_secs=0`，保留原可执行路径、代理、登录环境和监听地址。启动参数形式如下：

```bash
codex -c thread_unload_delay_secs=0 app-server --listen ws://127.0.0.1:8765
```

确认所有后端对话任务、网页终端和对话后台终端均已结束，再加载修改后的服务配置并重启：

```bash
systemctl --user daemon-reload
systemctl --user restart codex-app-server.service codex-lan-web.service
```

`restart-when-idle` 检查网页桥接观察到的任务和网页终端，后端的其他连接需一并核对。参数在后端启动时生效。详细说明见[对话占用与后端回收](https://github.com/hjd-hitsz/codex-web/blob/v2.1.1/docs/deployment.md#对话占用与后端回收)。

升级后刷新网页，在“设置 → 关于”分别核对网页和桥接版本，也可运行：

```bash
codex-web --version
codex-web version --json
curl http://127.0.0.1:8766/healthz
```

本版首次引入版本查询；后续升级可用这些信息核对磁盘安装包与运行进程。
