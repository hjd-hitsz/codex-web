# Codex Web v2.2.0

本版汇总自 v2.1.2 以来的文件查看、回复批注和对话管理改进。任务结束后可集中查看、编辑与撤销本轮文件变更，Markdown 文件默认显示排版预览；网页自动生成对话标题，并完善对话占用检查、外部归档同步和项目列表稳定性。安装、配置与服务管理沿用现有方式。

## 功能与修复

### 文件查看与变更

- 每轮任务结束后，以“已编辑文件”和紧凑列表汇总本轮文件变更，合并重复修改并显示增删行数；默认展示前 5 项，其余按需展开，标题可收起整个列表。回复的复制与分支操作统一放在汇总下方（[0a6c642](https://github.com/hjd-hitsz/codex-web/commit/0a6c642d37d92d22b4fbc32ea8673f8ade2b11a2)）。
- 点击文件名在右侧查看差异片段，点击右上箭头打开完整文件并定位到变更，点击独立源文件按钮查看当前正文；完整文件保留上下文与编辑能力，新增行显示绿色标记，删除内容在原位置只读展示，视图切换保留未保存内容（[0a6c642](https://github.com/hjd-hitsz/codex-web/commit/0a6c642d37d92d22b4fbc32ea8673f8ade2b11a2)）。
- 差异片段分别显示原文件与修改后文件的真实行号，隐藏区块坐标提示；同轮逐次补丁合成为净变更，处理重复编辑、已抵消修改和无关编辑造成的行号偏移，并支持查看已删除文件的差异（[0a6c642](https://github.com/hjd-hitsz/codex-web/commit/0a6c642d37d92d22b4fbc32ea8673f8ade2b11a2)）。
- 支持按文件撤销本轮修改：桥接重新读取已完成记录，在临时目录校验补丁并核对当前内容，冲突时保留当前文件；任务运行中暂停撤销，撤销结果同步各页面。文件变更汇总适用于 Git 仓库和普通目录，撤销校验需要服务环境可执行 `git`（[0a6c642](https://github.com/hjd-hitsz/codex-web/commit/0a6c642d37d92d22b4fbc32ea8673f8ade2b11a2)）。
- 右侧 Markdown 文件默认渲染表格、公式、代码块和 Mermaid，源码编辑与预览共用当前内容，切换保留未保存修改；相对链接和图片按文件目录解析。扩展常见代码、配置与脚本的语法高亮，适配深浅主题（[36da5ba](https://github.com/hjd-hitsz/codex-web/commit/36da5ba7833e8cd376d8577bb6923ea5f174f8e8)）。

### 回复与输入

- 选中助手回复文字后，可通过选区旁的浮动入口填写与发送批注；未发送批注自动保存，失败后可重试，运行中通过补充消息提交，并保留主输入框草稿与附件（[141f8d1](https://github.com/hjd-hitsz/codex-web/commit/141f8d1236a808bac7248c78e544b7a9061f77eb)）。
- 兼容桌面端回复批注格式，行内编号可展开查看对应原文和批注，历史用户消息中的批注显示为独立卡片；代码与公式中的批注标记保留原文（[141f8d1](https://github.com/hjd-hitsz/codex-web/commit/141f8d1236a808bac7248c78e544b7a9061f77eb)）。
- Markdown 文字链接统一显示蓝色文字与类型图标，区分代码、配置、文档、表格、演示文稿、图片、音视频、压缩包、脚本、目录和网页；适配深浅主题及长路径换行，保留文件行号、文件打开与图片预览交互（[2da1fce](https://github.com/hjd-hitsz/codex-web/commit/2da1fceca983029f8d166cf7bf08150a70a45774)）。
- 收紧思考强度面板的内边距及标题、滑块、档位和说明之间的纵向间距，保留拖拽区域；同时减少“正在处理”标题与实时提示之间的留白（[acf2621](https://github.com/hjd-hitsz/codex-web/commit/acf2621e1df496914234c9a4f8a4999150fc592b)、[fd6bfbc](https://github.com/hjd-hitsz/codex-web/commit/fd6bfbcb15842417806b14f6f816c4f4e487e27c)）。

### 对话与项目管理

- 网页对话首次发送后自动生成并保存简短摘要标题，打开无标题历史时补齐；保留已有标题与手动重命名，通过独立临时会话生成，合并重复请求并处理取消和迟到结果。标题生成使用本机 Codex 登录与对话模型，会产生少量额外模型用量（[a0c1030](https://github.com/hjd-hitsz/codex-web/commit/a0c1030a07f3bee2c3797ebb9dcc643071b45510)）。
- 打开对话时先显示历史，再检查写入权并恢复设置；检查、占用或恢复失败期间，在发送框位置显示状态与重试入口，保留草稿和附件，检查成功后由用户继续发送。空闲对话释放订阅，下一次发送、整理上下文或审查前自动恢复，运行中的任务保持保护至完成（[6d53460](https://github.com/hjd-hitsz/codex-web/commit/6d53460968647e48693ac9280737e974a38de0d0)、[8f63168](https://github.com/hjd-hitsz/codex-web/commit/8f6316846c4bb178d6f48dbc6f8fa308af9e21a5)）。
- 接收其他客户端的归档通知及对应请求返回的已归档状态，自动刷新列表；正在查看的已归档聊天返回新建界面，保留本地未发送草稿和项目顺序，迟到响应按所属聊天隔离（[37f0073](https://github.com/hjd-hitsz/codex-web/commit/37f0073774c2cf4342805efd2d7042fe1fa9fc50)）。
- 页面首次加载时根据全部未归档对话确定项目列表与顺序；本次页面内归档、恢复、任务完成和重连保留已有项目与顺序，全部归档后保留空项目及新建入口，新增项目放到开头；刷新页面时重新确定列表，并保留手动添加的项目（[c2170f8](https://github.com/hjd-hitsz/codex-web/commit/c2170f8226a19830019688bd98d4f3dd799b698e)）。

## 环境与安装

目标环境：Linux、Node.js 24+、npm、Git、已安装并登录的 Codex CLI，以及 `/usr/bin/zsh`；后台服务使用 systemd。本项目已在 Codex CLI `0.162.1` 上验证。

```bash
npm install -g https://github.com/hjd-hitsz/codex-web/releases/download/v2.2.0/codex-web-2.2.0.tgz
codex-web service install
loginctl enable-linger "$USER"
codex-web service status
```

`loginctl enable-linger` 用于开机启动用户服务及退出登录后继续运行，可能需要管理员授权。启动后访问 `http://电脑IP:8766`，本机可访问 `http://127.0.0.1:8766`。

## 从 v2.1.2 升级

安装新版、更新服务中的安装路径，并等待当前网页任务与终端结束后重启网页服务，以加载新的桥接接口和界面：

```bash
npm install -g https://github.com/hjd-hitsz/codex-web/releases/download/v2.2.0/codex-web-2.2.0.tgz
codex-web service install
codex-web service restart-when-idle
```

用户配置保存在独立配置目录。刷新网页后，在“设置 → 关于”分别核对网页和桥接均为 `2.2.0`，也可查看磁盘安装包与运行进程的来源：

```bash
codex-web --version
codex-web version --json
curl http://127.0.0.1:8766/healthz
```

已有 Codex 后端服务的启动参数按[对话占用与后端回收说明](https://github.com/hjd-hitsz/codex-web/blob/v2.2.0/docs/deployment.md#对话占用与后端回收)核对，使用 `thread_unload_delay_secs=0` 及时回收无订阅的空闲对话。需要调整后端时，先结束所有相关客户端的任务与终端，再重启后端服务。
