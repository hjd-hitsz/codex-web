# 架构说明

```text
浏览器 React 客户端
    │ HTTP 静态资源、WebSocket /rpc
    ▼
Node.js 网页桥接服务
    │ WebSocket JSON-RPC
    ▼
本机 Codex app-server
    ├─ 聊天记录、模型调用与工具执行
    ├─ 文件、Git 与交互式 shell
    └─ 已登录账户和已安装技能
```

## 前端

`message-link.jsx` 为 Markdown 中所有文字链接添加行内类型图标。本地引用根据扩展名与常见文件名区分代码、配置、文档、表格、演示文稿、图片、音视频、压缩包和脚本，末尾带斜杠的目录引用显示文件夹，其他本地类型显示通用文件图标；网页、邮箱与页内锚点分别使用对应图标。链接文字与图标共用深浅主题的蓝色变量，悬浮时显示下划线和强调颜色，长路径保持自然换行；链接内的行内代码使用透明背景。地址行号后缀保留在链接文字中，绝对路径点击继续打开文件面板，悬浮提示显示完整地址或 Markdown 指定的标题。仅包含图片的链接保持图片预览交互。

`client/src/main.jsx` 负责应用布局、项目侧栏、对话管理和设置弹窗；`chat.jsx` 负责消息、工作过程、输入框及交互请求；`workspace.jsx` 负责文件编辑、差异和终端。

`account-usage.jsx` 在侧栏底部的账户行旁，以圆环和下方百分比显示实际额度窗口。圆环中心用“周”或“5h”等缩写标记窗口，弧长表示剩余比例；默认折叠，点击圆环组展开上方的详情卡片，再次点击、点击外部或按 Esc 收起。入口使用按钮与 `aria-expanded`，支持 Enter 和空格，Esc 将焦点返回入口；切换账户和打开设置均收起详情。详情采用定位布局，展开和收起保持账户行高度，宽度适应侧栏和单行重置信息，窄屏受应用容器约束。

额度详情通过 `UsageMeters` 展示，每个窗口的重置信息在同一行显示“倒计时 · 具体日期时间”，日期采用浏览器本地时区。详情打开期间每 30 秒独立更新倒计时，回到前台立即校准本地时间；收起或卸载清理计时器与监听，更新倒计时沿用已读的重置时间。方案、额度窗口、已用比例和重置时间来自 `account/rateLimits/read`，优先显示 `rateLimitsByLimitId.codex`，兼容旧版 `rateLimits`；`account-usage.js` 按 `windowDurationMins` 命名窗口，10080 分钟显示周额度，300 分钟显示 5 小时额度。窗口按实际返回显示，将已用比例换算为剩余比例并限制在 0–100% 内；剩余不超过 10% 使用低额度颜色。API Key 账户显示类型，缺少窗口时以占位圆环及详情状态表示读取情况。

连接就绪后立即读取额度；页面可见期间每 60 秒校准，窗口获得焦点、页面回到前台、任意轮次完成及窗口重置时间后一秒再次读取。后台页面暂停定时读取，断线或卸载清理定时器和监听。`store.js` 合并并发读取，请求超时为 20 秒；完整读取替换快照，`account/rateLimits/updated` 按桶合并可用字段，通知中的 `null` 保留已有方案、窗口和重置元数据。通知版本、连接实例及账户变更共同隔离迟到响应；`account/updated` 清理旧快照并重新读取账户和额度。读取失败保留数据并显示“待更新”，后续自动读取恢复后清除状态，设置页保留外观、快捷键与版本信息，账户和额度集中在侧栏展示。

协议字段以本机 Codex CLI 0.162.1 的 `codex app-server generate-ts` 输出为核查依据：`GetAccountRateLimitsResponse` 提供完整快照，`AccountRateLimitsUpdatedNotification` 明确采用稀疏更新语义。生成文件仅用于本地核查，测试使用独立构造的账户与额度数据。

`sidebar-resize.jsx` 提供项目侧栏的相对宽度偏好和边缘分隔条。`style.css` 统一定义尺寸规则：自动宽度以应用容器的 20% 为参考，限制在 17–24rem 之间；桌面最小宽度为 17rem，最大宽度同时受 36rem、容器宽度的 40% 和聊天区至少 32rem 的空间约束。实际宽度为自动宽度乘以用户调节比例后应用边界。应用容器在 62rem 及以下切换为覆盖式侧栏，宽度同时受 24rem、容器的 85% 和外部留白约束；该条件随字体尺寸变化。浏览器页面缩放由 CSS 布局处理。

组件通过隐藏尺寸参考元素读取 CSS 实际计算的自动宽度和 1rem 步长，用 `ResizeObserver` 跟踪容器、参考元素及侧栏，统一更新拖动边界和无障碍数值。桌面使用 Pointer Events 与指针捕获跟踪鼠标、触控笔及触屏拖动；方向键每次调整 1rem，Home/End 到达边界，双击清除偏好并恢复自动宽度。`localStorage` 的 `cx-sidebar-width` 保存 `{ scale }`，旧版像素数值在首次显示时按当时的自动宽度迁移。窗口或字体变化时重新计算实际宽度，保留用户比例；结束、指针取消、捕获丢失、失焦、布局约束变化和卸载时清理拖动状态。覆盖式侧栏隐藏分隔条，桌面偏好继续保留。

`context-panel.jsx` 提供统一的右侧对话详情卡片，集中提供文件、变更和终端入口，并列出当前主对话中的子代理。`Conversation` 的上方布局容纳消息区和详情区域，输入框作为独立的下方整行横跨聊天工作区。主消息滚动容器覆盖整个上方工作区，原生纵向滚动条贴最右边缘，右侧卡片独立定位。消息列按卡片和导航自身宽度预留内容空间：桌面导航宽 36 像素，窄屏宽 30 像素，滚动容器使用稳定的原生滚动条槽。卡片定位单独计入导航到右边缘的距离，详情宽度使用上方工作区的容器查询单位。正文到导航或卡片的空隙与左侧边距保持一致，回到最新消息的按钮以可读消息列居中。

折叠通过 `store.js` 的共享状态更新统一关闭当前详情，清除 `panel` 和 `panelAgent`，再次展开显示工作区概览。常驻工具栏箭头、详情关闭按钮和 Esc 使用相同的折叠语义；Esc 关闭后将焦点交回常驻箭头。文件面板首次打开后保持挂载，折叠、返回概览和切换详情均保留未保存内容；重新点击文件入口可继续编辑。子代理详情随折叠卸载，清理监听并隔离迟到读取结果。

最右侧的 `context-tools` 工具栏始终提供文件、变更、终端和展开/折叠四个按钮，概览与详情打开时继续显示。文件与变更按钮首次点击打开对应面板，重复点击当前选中按钮通过共享折叠状态关闭详情，点击另一按钮直接切换面板；高亮和 `aria-pressed` 随当前面板同步，折叠时清除。终端按钮独立切换并显示开关状态。箭头在展开时朝右、收起时朝左，提示和 `aria-expanded` 随实际状态同步，重新展开回到概览。`ContextWorkspace` 在桌面和窄屏均默认折叠，展开与收起由显式共享状态控制；CSS 断点负责详情区域的尺寸和定位，视口变化保留用户选择。顶部仅保留新建对话按钮，卡片标题也省去重复的折叠入口。桌面与窄屏共用同一工具栏，导航固定在其下方并保持中心线对齐。工具栏高度和导航位置由共享 CSS 尺寸计算，展开与收起保持锚点稳定及独立点击区域。

界面字号与间距以根字号为基准使用 `rem`，根字号初始为 13px；默认尺寸沿用既有密度。文字行高采用无单位倍率：普通控件 1.5，侧栏主导航、项目标题与对话标题 1.3，正文和提问约 1.667，工具摘要及辅助文字约 1.667，子代理名称与状态 1.25，消息目录约 1.583。Markdown 段落继承正文行高，一级、二级标题为 1.222，三级标题为 1.3，四级标题与代码块为 1.5；工作记录等宽输出按其用途保留 1.6、1.65 或 1.7。设置说明和卡片正文保留各自的无单位倍率。

侧栏主导航最小条目高度约 2.462em，项目与对话条目约 2.154em；顶部栏、文件树、面板标题和标签栏均采用最小高度，由字体和内容共同撑开。行高表示文字行盒高度，条目高度还包含内边距及点击空间。侧栏分组、账号区、欢迎页、消息、工作过程、详情卡片、文件与差异面板、批注、图片预览工具栏、设置及搜索弹窗、快捷命令和底部输入区的 margin、padding 与 gap 使用字体相对单位；图像、视口与滚动容器的尺寸上限仍按各自布局规则约束。对话管理菜单以条目底部定位，随条目高度一起移动。

代码编辑器通过 `--code-font-size`（初始 12px）与 `--code-line-height`（1.4）控制文字和行号。终端从容器的计算样式读取字号与 `--terminal-line-height`（1），将实际行高除以字号转换为 xterm 的倍率；容器尺寸变化时同步排版并重新计算行列。输入框设置 `rows=2`，最小高度由两行文字和相对内边距共同确定，按内容测量高度，超过 180px 后内部滚动。验证分别覆盖基础字号、局部字号、80% 至 200% 的页面缩放及窄屏，并实际打开侧栏菜单、设置、文件面板和终端。

`sub-agents.js` 兼容 `subAgentActivity` 的启动、交互、中断与完成记录，以及 `collabAgentToolCall` 的目标和状态集合，按子代理对话 ID 合并重复活动。交互记录保留先前已知状态，缺失模型或思考强度时省略对应字段。工作过程中的中文动作行也能打开子代理对话。查看使用 `thread/read` 的元数据、`thread/items/list` 的全部正序分页和 `thread/turns/list` 的全部轮次元数据，复用 `chat.jsx` 的只读消息及工作过程渲染；消息图片与文件引用按子代理实际工作目录解析。

子代理查看使用独立组件状态和事件监听，沿用现有 WebSocket 连接，保持主对话 ID、草稿、附件及消息数组。只读视图省略发送、重新编辑和新增批注入口，读取期间收到的子代理事件与历史合并，后续消息、命令输出、思考摘要和轮次状态按子代理 ID 更新。切换子代理、关闭详情和切换主对话时卸载监听并丢弃迟到分页，断线时保留已读内容，重连后重新读取；页面提供刷新和失败重试。自动标题调度跳过具有 `parentThreadId` 或 `source.subAgent` 的子代理，读取子代理记录时保持其原有标题。

主对话和子代理详情通过 `thread-history.js` 读取完整消息历史，每页最多读取 100 条记录。优先使用 `thread/items/list`；后端明确返回该接口不受支持时，改用 `thread/turns/list`，传入 `itemsView: full` 并遍历全部分页。轮次按时间排序后展开，轮内消息保持原顺序，并补充所属 `turnId`。每次请求完成后核对当前对话或组件生命周期，切换后停止后续分页及回退请求；合并时保留读取期间收到的实时记录及更新。连接和其他读取错误继续交给原有重试入口。历史读取成功后独立检查写入权，其他客户端持锁时仍显示已保存消息。用户可连续向上滚动或拖动滚动条到达最早消息。`client/tests/thread-history.test.js` 和 `tests/components/history.mjs` 覆盖分页顺序、接口回退、写入占用时查看历史、实时更新及切换隔离。

`Conversation` 在布局阶段按滚动容器的 `scrollHeight` 定位最新消息，浏览器将位置限制在实际最大滚动值，包含消息列底部内边距。手动滚到底、打开历史和“回到最新消息”采用同一底部坐标。`ResizeObserver` 同时观察滚动容器与消息列，自动跟随期间在输入框恢复、图片或图表加载及窗口变化后保持真实底部。向上阅读超过底部跟随范围或点击目录后暂停跟随；手动回到底部后恢复。尺寸监听随对话切换、加载状态变化和组件卸载清理。`tests/components/conversation-scroll.mjs` 覆盖真实底部、延迟更新、容器与内容尺寸变化、历史阅读位置、返回底部和监听清理；浏览器回归使用生产构建与隔离分页历史，实际滚轮到底后触发延迟更新，并检查输入框恢复前后的底部距离。

`conversation-navigation.jsx` 在聊天工作区最右侧提供缩略目录，与消息区和详情区域同属上方布局；卡片展开、折叠及详情切换均保持目录靠右，并预留独立操作空间。桌面悬停或点击展开，触屏点击展开。`message-navigation.js` 从 `conversationGroups` 已确定的独立用户消息生成目录，保留提问与中途补充的顺序，已收纳的问题回答继续留在工作过程内；多段文字合并为空白规范化的标题，图片、技能及回复批注使用可读摘要。目录项显式采用 `justify-content: flex-start`，正文占用序号列之外的剩余宽度，使短标题与换行长标题保持一致的左侧起点。目录支持文本搜索、空结果提示、当前位置高亮及独立滚动，缩略标记最多显示当前消息附近的 12 项，弹层宽高限制在上方消息工作区内。

用户消息通过 `data-message-id` 提供稳定定位目标。点击目录后暂停自动跟随，将目标放在消息区顶部下方 20 像素，并将焦点移交该消息；后续流式更新保持阅读位置，“回到最新消息”沿用原有跟随逻辑。滚动事件通过动画帧合并，使用二分查找确定消息区顶部附近的当前提问，底部 100 像素内采用最后一条提问，与聊天自动跟随区域一致。`ResizeObserver` 跟踪消息列与容器的尺寸变化，适应展开过程、图片加载和窗口调整；正文流式更新复用已有监听。展开目录时仅滚动目录自身以显示当前项。Esc 关闭后恢复入口焦点，点击外部或焦点离开时收起；目录按对话 ID 挂载，切换与卸载时清理事件、观察器和待处理帧，空对话隐藏入口。

顶部操作栏常显新建对话的加号按钮，桌面侧栏收起和窄屏均可使用。该入口调用 `newChat(undefined, { reuseDirectory: true })` 沿用当前执行目录；未分类对话已有工作目录时，将该目录保存在 `projectlessCwd` 中，首次发送复用目录并继续携带未分类来源标记。尚未分配目录时，首次发送仍通过 `lan/projectless/prepare` 创建目录。侧栏分组、全局新建和快捷键继续沿用原有目录选择规则。

`turn-file-changes.jsx` 在轮次最后一组消息后展示一个“已编辑文件”汇总，标题包含文件数量并可收起整个列表。文件以紧凑单行列表排列，名称、增删行数和图标操作同行显示；长文件名截断，悬浮提示保留完整路径。默认最多显示 5 项，通过底部按钮展开其余文件或收回前 5 项，使默认展示高度保持稳定。文件路径、可选的原路径、该轮差异正文和独立的逐次补丁数组 `patches` 作为 `panelFile` 对象传给右侧文件面板；点击文件名指定 `view: "diff"` 查看差异片段，点击行尾右上箭头指定 `view: "full"` 打开完整文件并标记变更。源文件按钮发送字符串路径以打开普通文件。聊天列表仅承担摘要和操作入口，撤销使用小图标入口。

`workspace.jsx` 的 `FilePanel` 将 `panelFile` 字符串请求用于普通文件打开，并清除本轮装饰；对象请求按 `view` 区分差异片段和完整文件，缺少 `view` 时使用差异片段。差异视图直接使用所属轮次的记录，显示完整路径、增删行及复制入口，支持已删除的文件。完整文件通过 `fs/readFile` 读取当前内容并将本轮差异和逐次补丁交给编辑器，顶部提供差异片段与普通源文件按钮；差异片段视图分别提供全文变更和普通源文件按钮。Markdown 使用源码视图展示变更标记，普通文件打开继续使用预览。切换差异时保留原编辑器的文本和未保存状态，返回原文件继续编辑。打开其他文件时沿用放弃修改的确认；打开原文件时恢复未保存内容，已保存的文件重新读取磁盘中的当前版本。差异选择、返回编辑器和面板卸载会更新读取序号，迟到的文件读取结果按序号忽略。文件列表的展开与收起保持侧栏选中的差异，面板布局适配深浅主题和窄屏。

`file-changes.js` 中的 `fileChangeHighlights` 使用 jsdiff 将逐次补丁逆序应用到当前正文，得到轮次开始前的内容，再计算两者的净行差异，生成新增行及删除内容的插入位置。中间版本和已抵消修改合并处理，补丁按内容匹配无关编辑造成的行号偏移；实时净差异使用单个补丁。`file-change-marks.js` 将结果转换为 CodeMirror 的行装饰和只读删除块，保留完整上下文，删除块同时显示原文件行号。装饰随编辑位置映射，源文档始终保持当前文件正文；保存与普通复制使用编辑器文档。`code-editor.jsx` 使用独立的扩展配置区切换本轮标记，并定位到首处变更。载入的正文与差异记录冲突时省略错位标记，文件面板提示内容变化，原始差异片段继续可用。

共享的 `DiffBlock` 通过 `file-changes.js` 的 `diffRows` 解析统一差异的区块坐标，左列显示原文件行号，右列显示修改后文件行号。删除行只推进原行号，新增行只推进新行号，上下文行推进两者；每个区块及文件分别恢复起点，元数据保持无行号。区块坐标行在视图中隐藏，增删内容保留高亮，复制与撤销继续使用完整原始差异。

`store.js` 维护共享状态和 JSON-RPC 连接，处理历史加载、实时通知及重连。请求发送前统一经过 `execution-policy.js`：对话生命周期和任务使用完全访问、无需审批，直接命令使用完全访问沙箱策略。

连接初始化捕获开始时的对话选择和连接版本。模型与配置返回、列表加载完成后核对连接版本；恢复对话前同时检查选择版本与发送状态，避免迟到的初始化重新读取或恢复首条消息尚在提交的新会话。切换后的发送错误按原选择隔离。每个 WebSocket 的消息、关闭和重连回调仅操作所属连接，RPC 发送还核对实际 `readyState`。`tests/components/connection-lifecycle.mjs` 通过延迟列表与纯文字首次发送验证恢复顺序，并覆盖旧连接事件和已关闭连接的发送保护。

连接恢复时，已显示的当前对话并行执行 `loadHistory` 与后台 `refreshThreadAccess`，保留消息和输入框的组件实例、工作过程展开状态、阅读位置、草稿与附件。后台写入检查沿用 `threadAccess` 的 `checking` 状态，以 `background` 标记保留可编辑输入框并禁用发送；检查成功恢复发送，实际占用或失败显示现有状态区。首次打开对话继续使用完整加载流程。历史合并记录读取前的消息对象：后端历史更新已有内容，读取期间发生变化的实时记录优先，缺少历史记录的本地消息继续保留。历史、写入检查及轮次列表核对连接实例、初始化版本与对话选择，丢弃旧恢复任务的迟到结果；历史同步失败保留当前内容并显示实际错误。`tests/components/connection-recovery.mjs` 覆盖状态保留、历史补齐、实时更新、失败、再次断线与切换隔离，`tests/browser/connection-recovery.mjs` 使用生产构建验证桌面和窄屏的前后台切换及实际断线恢复。

打开对话先通过 `thread/read` 和 `thread/items/list` 显示历史，再调用 `thread/resume` 检查写入权、读取有效设置并接入当前后端的活动轮次。`threadAccess` 记录所属对话与加载、检查、可用、占用或失败状态；首次加载与手动重试的检查期间、写入占用和恢复失败时，`Composer` 用状态区替代发送框，并提供“重试”按钮。消息区域直接保留历史，其他进程保存的进行中轮次仅用于展示。`refreshThreadAccess` 在原对话上重新检查，检查期间阻止重复请求，保留草稿与附件，成功后恢复输入框，由用户决定何时发送；历史读取失败时重试完整加载。重试保留已选速度，恢复设置的迟到结果受对话打开序号和当前检查对象约束，期间用户调整的模型、思考强度继续保持已选值。

`sendMessage` 同时检查加载与写入状态，覆盖输入框快捷键和问题回答等入口。检查成功后发生的新写入冲突同样切换到占用区，移除未确认的临时消息并保留草稿与附件。检查结果按轮次事件修订号保护实时状态，旧检查与轮次列表的迟到响应保持隔离。

速度模式独立于模型和思考强度，保存在 `store.js` 的 `serviceTier` 状态中。首次连接从 `config/read.config.service_tier` 初始化，恢复对话以 `thread/resume.serviceTier` 为准，当前对话的 `thread/settings/updated` 通知同步其他页面的变化；重连保留网页已选的标准速度。`service-tier.js` 从模型目录的 `serviceTiers` 获取能力，旧目录使用 `additionalSpeedTiers`，将 Fast 的 `fast` / `priority` 别名解析为目录公布的 ID。`service-tier-toggle.jsx` 在输入框和模型弹窗提供闪电图标，点击切换标准与 Fast；绿色实心表示加速，灰色描边表示标准，通过 `aria-pressed` 和悬浮提示报告状态。模型未提供 Fast 时禁用开启入口，恢复的其他档位保留原值并在提示中显示名称，点击可切回标准。切换模型时保留新模型支持的档位，否则恢复标准。

`reasoning-effort.jsx` 在输入框提供紧凑的思考强度入口，展开后使用原生 `range` 滑块按模型的 `supportedReasoningEfforts` 逐档调整；模型设置弹窗直接显示同一滑块。未显式选择时显示模型默认强度，修改后更新 `effort` 并随下一轮任务发送。滑块支持指针拖动和方向键；切换模型或对话时收起浮层，焦点移出或按 Escape 同样收起。单一档位的模型显示固定强度。输入框移除技能按钮，技能入口保留在侧栏和快捷命令中；窄屏保持思考强度、速度与计划模式可用。

`thread/start` 和 `turn/start` 显式传入 `serviceTier`，选择标准时传 `null` 清除已有档位，避免省略字段后继续继承 Fast。速度选择作用于下一轮任务；`turn/steer` 继续只提交补充内容，沿用正在运行的轮次速度。速度配置使用现有 Codex 后端，无需额外模型请求或修改全局配置。[官方速度说明](https://learn.chatgpt.com/docs/agent-configuration/speed)介绍 Fast 模式及用量。

输入框草稿保存在浏览器 localStorage：尚未创建对话时使用 `cx-draft-new`，已有对话使用 `cx-draft-<threadId>`。`thread/start` 成功后，将当前草稿转存到实际对话 ID 并移除新对话草稿；目录分配或创建失败时继续保留新对话草稿，轮次发送失败时可从对应对话恢复。发送成功后，仅清理内容与已发送文本一致的草稿，即使页面已切换对话也清理原对话记录；等待期间继续编辑的内容与其他对话的草稿保持可恢复。异步问题回答使用 `clearDraft: false` 保留输入框内容。

`conversation-groups.js` 按 `turnId` 汇总中间活动，每轮保留一个默认折叠的过程区域。普通用户消息独立显示，过程区域移至该轮最后一条普通用户消息下方；运行中的待答提问紧随所属过程，最终回答保持独立。提问本身即可创建过程区域，区域 ID 以轮次为依据，在后移、提问出现与回答后保持稳定，保留展开状态。已回答的提问及其生成的回答消息合并为过程内的记录；未回答的异步提问在所属轮次完成、失败或中断后同样收入过程。分组读取轮次列表和各分页恢复的状态及结束时间，历史中明确的 `final_answer` 也可确认轮次结束；缺少结束依据时保留待答卡片。结束判断按轮次隔离，新轮次的待答卡片保持独立。`store.js` 为待确认的引导消息附上正在运行的轮次 ID，使发送等待期间与历史恢复后的排列一致。缺少轮次信息的历史活动仅合并相邻记录。

`chat.jsx` 仅在该组所属轮次正在生成且区域折叠时，在折叠区外显示最新一条有效活动，随流式更新替换；最新活动为多段思考摘要时仅显示最后一段，已结束提问始终留在过程内部。实时预览由 `.process-preview` 单独控制紧凑布局，标题下方保留 2px 间距，并清除预览容器的上下内边距与首尾活动的外边距。轮次结束后收起预览，展开过程区域可显示全部记录。`reasoning-summary.js` 提取摘要标题和正文，`message-actions.js` 决定最终回答的复制与分支按钮。`chat.jsx` 在本轮最后一组消息之后依次放置 `TurnFileChanges` 和 `ReplyActions`，操作栏绑定该轮最终回答；文件汇总、流式完成与历史恢复使用相同顺序，无文件变更时操作栏仍位于结果末尾。

`command-description.js` 在浏览器本地将常见 shell 命令转成中文操作描述。解析保留引号和转义后的参数，识别静态的 shell `-c` 包装，以及 `cat`、`sed -n`、`head`、`tail`、`rg`、`grep`、`ls`、`find` 等读取与搜索操作；`SKILL.md` 显示“阅读技能”及所在技能目录名，标题省略技能文件路径，指定行读取继续保留行范围。`command-operations.js` 识别 Git 差异、空白错误检查、暂存区、状态与提交记录，npm 检查、测试、构建和 Prettier 格式操作，以及进程、服务、日志、磁盘和网络查询；同时识别解释器、`uv run` 与常见环境包装。参数按命令分别识别，描述保留操作对象、目录、工作区和必要范围，未知用途及选项继续显示原文。

组合命令按 `;`、换行、`&&`、`||` 和管道的关系连接描述，其中未知片段保留命令原文。包含重定向、子 shell、命令替换或复杂控制流的 shell 命令整体保留原文。实时提示和历史活动共用该描述，展开详情始终展示完整原始命令、输出、退出码与工作目录。扩充规则可依据本机 rollout 的命令类别和频次确定优先级，回归测试使用独立构造的命令样例。

`user-input.jsx` 提供提问表单，区分选项与自定义输入，支持多行文本、私密字段、多问题校验和 Ctrl+Enter 提交。阻塞提问等待用户选择；非阻塞提问预选首项，提交由用户触发。单选组按表单实例隔离。提问框与结束记录的主要文字共用 `--chat-font-size` 和 `--chat-line-height`，题干段落继承卡片行高，选项标题和多行输入沿用相同排版；正文行高使用无单位倍率 `--chat-line-height`（约 1.667），由各元素实际字号计算；15px 正文对应 25px 行高。提问摘要、工具记录和辅助说明共用无单位倍率 `--aux-line-height`（约 1.667）；摘要与工具记录桌面字号为 12px、窄屏为 11px，辅助说明字号为 12px。单独调整字号时，行高与输入框基于 `lh` 的最小高度随之变化。选项框采用 5px 上下内边距与 3px 纵向间隔。已答提问直接排列在过程活动中，移除助手消息包装，复用 `.activity` 和 `.activity-summary`，使收起行与相邻工具记录保持相同高度、外间距和图文间距，相关正文在展开后缩进显示。

提问有两种协议来源。`item/tool/requestUserInput` 属于服务器请求，按原请求 ID 返回 `{ answers: { [questionId]: { answers: [text] } } }`；`isBlocking` 控制等待提示和选项初始状态，`isOther` 控制自定义回答入口，`isSecret` 使用密码字段。待处理请求从 `lan/state.questions` 恢复。当前页面将提交成功、`serverRequest/resolved`、`lan/questionResolved` 或状态快照移除的请求记录为 `userInputRequest`，收入所属过程，字符串与数字 ID 按同一标识处理。`QuestionRecord` 使用原生 `details` 和 `summary` 提供独立的默认折叠记录；展开外层过程时仅显示提问摘要，点击摘要后展示原问题、全部选项、已选标记与实际回答，异步提问的补充正文一同收纳；其他页面解决的请求保留结束状态和选项，私密字段仅显示提交状态。这些同步结束记录保存在当前对话的页面内存中，切换或刷新后以重新读取的后端历史为准。连接不可用或发送失败时保留表单，恢复后可重试。[官方协议说明](https://learn.chatgpt.com/docs/app-server#toolrequestuserinput)介绍请求与解决通知的对应关系。

异步工具的问题放在 `agentMessage.questions`，字段为 `title` 和可选的字符串选项列表。所属轮次运行时，包含问题的消息在过程下方独立展开，空正文同样显示，后续助手进度保持卡片可见，正文与题干完全相同时仅展示卡片题干。回答按问题标题和“回答：”整理为普通用户消息：任务运行时调用 `turn/steer`，空闲时调用 `turn/start`。提交过程保留输入框草稿与附件；成功响应立即在原问题保存本地答案并收入过程，失败保持可重试表单。轮次结束后，未回答的问题使用默认折叠的 `QuestionRecord`，摘要显示“提问已结束”，原文与选项保留在记录内；点击“补充回答”后才显示填写表单。异步表单在页面内按对话和消息标识保存未提交内容，过程收纳导致表单重新挂载时恢复，成功发送后清除，刷新页面后重新读取历史。`question-state.js` 从历史消息按顺序匹配完整问题批次及多行回答，一条回答仅归属最近一批匹配的问题，当前页面发送时附带的本地问题标识优先。匹配的回答与问题一同收纳，其他运行中问题继续保留回答入口，普通补充消息保持独立。已答记录及其选项通过 `QuestionRecord` 展示。

`thread-order.js` 从 `thread/turns/list` 的 `completedAt` 取得最近轮次结束时间，统一用于侧栏对话、搜索结果、项目分组初始排序和时间展示。成功、失败和中断轮次均参与排序，运行中轮次沿用上次结束时间；缺少结束记录时使用创建时间。打开对话产生的 `updatedAt` 变化仅用于缓存失效。

`store.js` 首次成功加载未归档列表时，从分页展示前的全部对话确定 `projectOrder`，在当前页面内存中保存项目列表与顺序。`projectGroups` 以该快照和手动添加的项目创建分组，再填入当前对话，因此归档全部对话后仍保留原位置的空项目与新建入口。归档、恢复、置顶、任务完成、列表刷新和断线重连均沿用已有项目和顺序，新增项目放到列表开头；归档视图共用该快照。项目内对话继续按完成时间更新顺序，刷新或重新打开页面时根据当时的未归档对话重新确定项目列表与顺序，浏览器保存的手动添加项目继续保留。

对话列表先按创建时间遍历后端分页，再读取轮次元数据（`itemsView: notLoaded`，最多六个并发请求），按结束时间排序后每次展示 60 条，确保后端分页中的较新完成记录进入首页。轮次读取结果按对话 ID 和 `updatedAt` 缓存，完成通知立即更新排序并刷新列表；旧列表请求的迟到响应会被丢弃。读取失败时保留已知结束时间或使用创建时间，下次加载重试。首次读取成本随历史记录量增长，后续加载复用未变化对话的缓存。

每次加载列表同时请求桥接的 `lan/projectless/read`，取得桌面端自动工作目录与对话 ID 的对应关系。`thread-projects.mjs` 只读 `CODEX_HOME/.codex-global-state.json`，未设置 `CODEX_HOME` 时使用当前用户的 `~/.codex`。识别条件为：对话在 `projectless-thread-ids` 中、具有 `thread-projectless-output-directories` 和 `thread-workspace-root-hints`、输出目录为工作区根下的“日期/对话目录/outputs”，且没有 `thread-project-assignments` 项目归属。状态文件缺失、暂不可读或内容不完整时返回空映射；分组元数据请求失败时，列表仍按实际目录加载，后续加载重新读取。

`thread-order.js` 将当前 `cwd` 仍等于自动工作目录、且未通过 `projectId` 或网页项目列表指定项目的对话合并到空路径分组。`project-group.jsx` 将该分组显示为“未分类”，支持折叠与新建对话，空分组保留入口。CLI 和外部端对话按明确的工作目录分组，只有无项目标记的外部对话也遵循此规则。工作目录已改变或已进入自动目录内具体项目的对话按当前目录分组；缺少目录的对话进入“未分类”。分组只影响侧栏展示，执行任务和文件操作继续使用实际 `cwd`。

从“未分类”新建时，浏览器保存无项目选择，输入框和顶部目录入口显示“未分类”。首次发送通过 `lan/projectless/prepare` 在 `CODEX_HOME/codex-web/workspaces` 下创建独立的 `chat-XXXXXX` 工作目录，再以该 `cwd` 和 `threadSource: codex-web-projectless` 调用普通 `thread/start`。后端保存来源字段，`lan/state.projectlessRoot` 提供自动目录根。分组要求当前目录为该根下直接生成的六位字母数字后缀目录，并匹配无项目来源；当 `threadSource` 为 `null` 或缺失时，使用创建者 `originator: codex_lan_web` 补充识别。这覆盖了同一对话的 `thread/read` 返回完整来源、`thread/list` 返回 `null` 的接口差异，使重载、归档恢复和新浏览器连接后仍能恢复分类。明确项目归属继续优先，其他创建者、其他目录与自动目录内的子项目按实际目录分组。

目录分配失败保留草稿；对话创建失败时重试复用已分配目录。网页新建与桌面端识别共用项目归属优先规则，选择具体文件夹后按目录创建。桌面状态文件继续只读，网页工作目录独立管理。

`summary-translator.js` 在浏览器中将代码、路径、链接和 Markdown 强调标记替换为占位符，再向本站 `POST /api/translate` 提交 `{ texts }`，收到 `{ translations }` 后原样恢复保护内容；占位符缺失或重复时按失败处理。长正文在保护内容后按最多 1000 字符分段，优先在换行或空格处拆分，保留段落空白、完整 Unicode 字符和完整占位符；每个请求最多 3000 字符与 24 条，避免历史摘要批量重译触发远端长度限制，响应按原顺序拼回对应正文。桥接的 `summary-translation.mjs` 通过 Node.js 直接请求 TranSmart 的 `https://transmart.qq.com/api/imt` HTTP API，将英文摘要译为简体中文，使用普通机器翻译 `model_category: normal`、随机生成的匿名客户端标识及空的 `user` 和 `session`，免登录、免密钥。接口用法见[腾讯 AI Lab 的 TranSmart 技术报告第 4 节](https://arxiv.org/html/2105.13072v1#S4)。浏览器请求超时为 12 秒，远程请求超时为 10 秒；本站校验请求方法、最多 24 条非空文本和 256 KiB 的请求体，远程失败返回可重试错误。翻译路由独立于 Codex 后端连接状态，开发时由 Vite 代理至桥接；旧桥接返回纯文本 404 时，前端提示等待网页服务更新。

翻译调度器以完整原文为键，分别管理排队与执行中的请求，以及已经成功完成的译文。相同原文共享尚未完成的请求，成功后写入内存缓存与当前标签页的 `sessionStorage`，会话存储键为 `cx-summary-zh-session-v1`。工作过程折叠会卸载摘要组件，再次展开、切换对话、重新挂载组件和刷新页面均直接复用会话译文，缓存命中时立即展示标题与正文。组件卸载后返回的成功译文仍会保存；失败请求仅清理进行中记录，后续可以重试。关闭标签页或浏览器后结束缓存会话，新页面重新翻译；存储被禁用、不可读或已满时，译文继续保留在当前页面内存中。页面初始化清理旧版 `cx-summary-zh-v1` 持久化缓存。

调度同时按正文总长度限制批次，批量请求失败后拆为单条重新调度，分别完成或报告失败，保持并发限制和标题优先，其他摘要继续取得译文。

`use-summary-translation.js` 为标题使用最高优先级：到达后立即入队，在下一个事件循环发送，并可越过待处理正文；同一原文已在正文队列时提升优先级并复用请求。正文首次显示即主动入队，折叠时同样翻译，以 100 毫秒窗口合并请求。队列最多并发两个请求，正文最多占用一个，为新标题保留容量。单个标题或正文各自最多保留一个待完成请求，完成后读取最新文本，省略积压的中间版本；正文后续请求的开始间隔至少为 300 毫秒，持续流式更新也按此间隔推进，等待期间继续展示已译前缀。翻译独立于 Codex 对话、账户和模型选择，失败时展示原文并提供重试入口。

`ProcessDuration` 在工作过程标题内显示计时。运行时每秒根据轮次开始时间更新已用时，完成、失败或中断后固定显示总耗时；展开和折叠共用同一个计时组件，结束和卸载后清理计时器。`turn-timing.js` 优先采用后端的 `durationMs`，其次用秒级 `startedAt` 与 `completedAt` 相减；缺少完整时间记录的历史省略耗时。`store.js` 将现有 `thread/turns/list` 响应中的时间字段按对话 ID、轮次 ID 保存到 `turnTimings`，复用排序时读取的全部历史分页。开始、完成通知和发送响应同步实时记录，缺少时间字段的实时通知使用本机接收时间；后续后端时间记录可补齐精度，缺省字段保留已有记录。

## 桥接服务

`file-types.mjs` 供前后端共用文件类型与 MIME 定义。`file-preview.jsx` 使用原生图片、音频、视频和 PDF 预览，提供原文件下载及加载失败重试；Office 文档、压缩包和其他已识别二进制文件直接显示下载入口。未知扩展名通过 `fs/readFile` 读取后检查 UTF-8 和控制字节，二进制内容转为下载，普通文本继续使用编辑器。预览跳过文本保存；媒体在切换、关闭或重试时暂停并清除地址，终止旧资源读取。文件打开保留未保存修改的确认和请求序号隔离。链接按显式目录、当前对话目录、所选目录及默认目录解析，本机 `file:` 和 `sandbox:` 链接也进入文件面板，Markdown 文件内的相对链接以文件目录为准。

`file-content.mjs` 通过本站 `/api/files?path=...` 流式读取绝对路径文件，保留 `/api/media` 作为已有视频地址的入口；开发服务器代理两种路径。GET 和 HEAD 返回实际 MIME、文件长度及 `Accept-Ranges: bytes`，单段 Range 支持起止、开放末尾及后缀，分别返回 206 或带文件大小的 416。原生预览类型使用 inline，其他内容和 `download=1` 请求使用 attachment，并通过编码后的 `filename*` 保留文件名；HTML 等源文件按二进制附件下载。响应使用 `no-store`、`nosniff`，SVG 额外限制脚本和外部资源。读取使用背压和连接取消清理，下载保留原始字节；浏览器自身的容器、编码及 PDF 阅读能力决定原生预览效果。

HTTP 服务提供构建资源和健康检查，支持构建目录根部的 JavaScript 与 CSS 文件，包括 Mermaid 按需加载的分块；资源路径限于单个文件名，缺失资源返回 404。资源使用 gzip 传输，并按修改时间刷新内存缓存。WebSocket 网关为不同浏览器客户端重新分配请求 ID，再将官方后端的响应路由回发起客户端；通知广播给所有已连接网页。

`rpc-transport.mjs` 将超过 1 MiB 的 JSON 文本拆成连续的 WebSocket 文本帧，首帧使用文本操作码，后续为 continuation，最后一帧设置 FIN；按 UTF-8 字节切分，接收方重组后再解码整条消息。Codex CLI 0.162.1 实测在单帧超过 16 MiB 时关闭连接，分帧后的 17 MiB 和 63 MiB 请求正常返回，65 MiB 整条消息仍触发关闭。桥接因此在转发前检查完整请求上限，并对较大消息同步排入小帧，避免不同消息的片段交错。`server/tests/rpc-transport.test.mjs` 从真实网络帧头验证边界、操作码与 FIN，并核对大图片及 Unicode 正文无损重组；订阅和组件测试覆盖超限后继续发送、其他页面连接以及草稿和附件保留。

桥接进程还保存活动轮次、待处理交互请求、终端运行状态与最近输出。网页重连时通过 `lan/state` 恢复这些状态。该缓存属于进程内运行状态，重启网页服务会重新建立后端连接。

后端 WebSocket 关闭时，桥接输出 `App-server disconnected` 结构化日志，包含关闭码、关闭原因与待处理请求方法，随后向对应网页返回断连错误并广播连接状态。日志省略请求正文和参数；内部恢复与取消订阅请求也保留方法名，便于定位中断环节。`server/tests/subscriptions.test.mjs` 使用模拟后端验证首次提交中断时的错误返回和日志内容。

`thread/start`、`thread/resume` 和 `thread/fork` 的成功响应记录实际返回的对话 ID。新建空对话在首次成功提交前保留订阅，以保护尚未落盘的会话和发送失败后的重试；页面关闭后释放。已有记录的对话空闲且恢复、发送等相关请求结束后，桥接调用 `thread/unsubscribe`，页面保持打开时也释放订阅。多个页面共享运行中的对话时，活动轮次和待处理请求继续保护该订阅，全部完成后释放。关闭页面和心跳超时均保留运行中的任务；页面关闭后的迟到响应同样触发清理。桥接每 30 秒发送 WebSocket ping，下一次检查仍未收到 pong 时断开失联连接。

`turn/start`、`thread/compact/start`、`review/start` 在转发前检查订阅，已释放的对话通过内部 `thread/resume` 恢复，并继续使用完全访问策略。同一对话的并发写入共用恢复请求，原请求在恢复期间登记为待处理，确保从恢复到提交之间持续保留订阅。正在取消订阅的对话等待释放响应后再恢复；恢复失败时保留后端错误并结束原请求，实际写入尚未提交。独立客户端持有的写入锁属于各自 Codex 进程，当前 0.162.1 协议没有跨进程接管参数；历史读取与网页订阅释放分别改善查看和网页端的空闲占用。

项目的后端启动脚本和新建 systemd 后端服务均传入 `-c thread_unload_delay_secs=0`；桥接也在对话生命周期请求中覆盖同名配置。当前使用的 Codex CLI 0.162.1 在启动参数设为零时及时卸载无订阅的空闲对话，仅在单次对话请求里设置该值仍会保留对话。已有后端服务继续保留原配置，升级时需核对启动参数，见 [部署与维护](deployment.md#对话占用与后端回收)。

## npm 分发与命令入口

根包通过 `bin/codex-web.mjs` 提供全局 `codex-web` 命令。源码继续使用 npm workspaces 管理前后端，发行包用 `files` 白名单包含 `client/dist` 和运行代码，安装时仅需要桥接的运行依赖。前端在打包前构建，目标机器直接提供已构建资源。

命令入口从用户配置目录加载 `.env`，然后调用桥接、后端启动或服务安装脚本。配置与 npm 安装目录分离，升级安装包保留用户配置。systemd 服务写入安装时的 Node.js 和入口绝对路径，网页服务记录用户配置目录；已有后端服务保留原配置。源码部署仍通过根目录 `.env` 和 npm scripts 工作。

## 版本来源与发布管理

版本来源和发布管理由根包版本与 Git 身份共同驱动。`server/src/version.mjs` 在源码仓库读取提交、工作区状态和匹配版本的 HEAD 标签；桥接在启动时固定这些信息，命令行在执行时读取，后端 `initialize.clientInfo.version` 使用同一可读标识。

Vite 在构建时把版本信息和构建时间同时写入前端常量及根目录 `build-info.json`，该文件随 npm 包交付，在目标机器缺少 Git 时恢复来源。源码运行优先读取实时 Git，避免历史清单覆盖当前身份。网页“关于”通过前端常量和 `lan/state.version` 分别展示网页与桥接信息，`/healthz.version` 提供运行中桥接的同一信息。

`scripts/version.mjs` 提供一致性检查、发布准备和正式标签校验。日常记录进入 `CHANGELOG.md` 的未发布区域，发布准备一次性归档变更、同步版本与下载地址，并生成详细发布说明草稿；GitHub Release 工作流从通过校验的稳定标签发布。完整规则见 [版本管理](versioning.md)。

同版本重复准备原样保留已审阅内容，尚未创建标签的准备批次会阻止继续递增。`scripts/publish-release.mjs` 在临时目录打包并生成 SHA-256，将附件上传到同版本 Release 草稿，两个附件完整上传后转为正式发布。上传中断后重试复用草稿，已正式发布的版本只检查附件存在性，保留原内容；查询失败或正式附件缺失时报告具体错误。

手动上下文整理由 `server/src/compaction.mjs` 记录按对话隔离的异步任务，`thread/compact/start` 确认后继续持有订阅，直到所属轮次完成、失败或中断。桥接通过 `lan/compaction` 广播状态，并在 `lan/state.compactions` 提供多页面与重连快照；同一对话整理期间暂停新的轮次、补充、审查和重复整理。后端重连及 `lan/compaction/check` 读取实际分页轮次，运行中的整理任务重新订阅。

`server/src/compaction-state.mjs` 为浏览器和桥接共用的纯状态核对逻辑，按已知轮次 ID 或提交时间匹配整理轮次，排除带有普通用户消息的轮次及其中的自动整理。客户端重连、回到前台及整理期间定期核对状态；支持整理快照的桥接使用 `lan/compaction/check` 并应用返回值，缺少快照或任务记录时通过 `thread/read` 和完整分页的 `thread/turns/list` 恢复。检查结果按连接、任务对象和轮次事件修订号隔离；空闲且缺少整理记录，或实际运行的是普通任务时解除遗留整理占用，显示结果待确认。状态卡片仅显示状态、耗时和必要操作；草稿保持可编辑，发送入口统一检查整理占用，任务结束后恢复发送。空闲重启脚本也检查整理任务，覆盖请求确认早于开始事件的间隙。

客户端在发送整理请求前，将按对话保存的未结束任务写入浏览器 `cx-compactions`，包含任务标识、提交时间、状态与已取得的轮次 ID。完整页面刷新从该记录恢复提示、耗时和发送限制，再由桥接快照或实际轮次记录核对；提交阶段的恢复任务也在连接就绪后立即核对，当前页面仍在等待提交响应时沿用请求保护。任务结束、归档或删除时同步移除对应恢复记录。兼容旧桥接时，刷新前已经发出的开始通知和刷新期间结束的任务均通过记录恢复。

`activity-content.jsx` 按工具的实际内容渲染工作过程。网页记录区分搜索、打开页面和页内查找，分别保留全部查询词、网页链接和查找文字；MCP、动态工具与函数结果按文字、图片、音频、资源链接和字段列表展示，嵌入的 JSON 文本先解析成可读内容。MCP 优先显示返回的内容块，内容块为空时使用结构化结果；空字段与内部元数据省略，失败保留实际错误。图片查看、图片生成及返回图片的工具默认展开，复用 `MessageImage` 的加载、重试与大图预览；实时返回图片时自动显示，用户主动收起后保留选择。审查、上下文整理、等待及钩子指令各自显示对应内容，其他工具使用通用字段展示。主对话、最新活动预览与只读子代理共用该组件；命令详情继续保留原始命令、输出、退出码及目录。
